<!--
I’d like to start with a story from very early in my career.
I was on a team that had onboarded Jenkins: a CI/CD server akin to self-hosted CircleCI or GitHub Actions.
At the time, the Jenkins web interface was -in my professional opinion- terrible. It was clunky, confusing, hard to use - I wanted us to use something better.
So I sent an email (this before Slack was popular) along the lines of:
Subject: “Why are we using Jenkins?”
Body: “The Jenkins UI is clunky, confusing, and hard to use. Surely there must be something better. Can we switch to that?”
To: my manager… and the entire dev team.
Oof! This was an act of “Complaining Negatively”. I had voiced negativity in an open forum without adequately backing it up or giving credit where credit is due for past efforts.
-->

<!--
My default sandwich presentation is three tiered:
Compliment the existing work (always compliment the thing you’re about to complain about – it makes you seem both positive and objective!)
Express grievances (in an optimistic, balanced way – don’t be unnecessarily bitter or defeatist)
Conclude by describing the better world you’re striving for (make it sound appealing)
An example:
“I see we’re using Jenkins for CI – and it’s integrated nicely with our Azure DevOps, emails, and Teams. These integrations have been really handy for getting status updates.”
“I’ve been having a hard time using specifically the web interface for Jenkins. It’s clunky, slow, etc. etc. – have we looked at improving this development flow?”
